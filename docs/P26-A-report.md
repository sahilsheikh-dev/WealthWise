# P26-A Accessibility and Performance Audit

## Scope and method

- Date: 2026-11-06.
- Source audit covered `app/**/*.tsx` and `src/components/**/*.tsx`.
- No changes were made and `app/(tabs)/index.tsx` and `app/(tabs)/budget.tsx`
  were not edited or scanned as implementation targets.
- Font-scale findings are source-level findings for 1.3x and 2.0x; native
  physical-device rendering remains unverified.
- Measurements use five samples and report the median.
- The benchmark was run with Node 26, React Native Jest/test-renderer, the
  demo fixture generated by `buildDemoData`, and the 50-year
  `createStressData` fixture.

## Accessibility inventory

Severity meanings:

- **High:** blocks identification, operation, error correction, or a
  common action.
- **Medium:** creates clipping, poor reachability, inconsistent focus, or
  ambiguous status at text scale.
- **Low:** minor consistency or navigation risk.

## Performance inventory

| Area | Finding | Evidence |
|---|---|---|
| Transactions | Full `ScrollView` plus grouped `.map()` rendering instead of virtualization for all transaction rows. | Long fixture render rebuilds groups and rows per render; memoized grouping exists for filtered rows, but the outer screen still is not virtualized. |
| Assets | Portfolio rows are memoized but derived schedule status, totals, sorting and card-model maps run on data/theme changes. | The screen uses memoized `rows` and `cardModels`; still reprojects every asset card on broad AppData changes. |
| Liabilities | Full `.map()` rendering, sorting and schedule/summary calculations for every liability on each relevant data change. | No virtualized list; broad AppData subscription rebuilds calculated rows. |
| Goals | Full `.map()` rendering, projections and shared-link calculation per goal. | Recomputes `goalView`, `goalProjection`, shared-link counts and sorting when any AppData changes. |
| Home | Protected source; broad AppData-derived summary and due/goal slices render on each store update. Report only. | `useAppData()` subscription is broad; user-owned file was not modified. |
| Budget | Protected source; full section/item `.map()` trees and chart calculations render in a `ScrollView`; report only. | Broad store/data derivation and large inline structures are source-visible; no edit authorized. |
| Emergency Fund, Insurance and other detail lists | Several screens use full row `.map()` trees rather than virtualized lists. | Stress fixtures are likely to produce long row trees; no native benchmark was available for these routes. |
| Shared store subscriptions | Screens using `useAppData()` without a selector receive every AppData change. | Broad subscriptions can cause unnecessary derivation and render work outside changed entities. |
| Large inline arrays | `filters.map`, sort options, category choices and chart/summary option arrays are allocated or reconstructed in render paths. | Most are module constants or memoized; remaining route-local arrays/options should be source-reviewed per screen. |
| Mount sync work | Store hydration, portfolio/schedule calculations and 50-year fixture construction can perform synchronous work before first paint. | Hydration measured 147ms median for the 50-year fixture in the Jest benchmark; demo hydration rounded to 0ms. |
